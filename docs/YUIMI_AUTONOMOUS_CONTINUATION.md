## 四、自主权和停止规则

### 可以自主执行

- 读取代码、报告、构建产物和本地上游副本。
- 运行依赖安装、测试、构建、本地预览和浏览器自动化。
- 为测试或报告添加小型脚本、快照和产物索引。
- 修复有明确复现证据的移植故障。
- 更新测试、报告、来源清单和第三方资源审计。
- 在当前 `codex/yuimi-exact-port-batch1` 分支创建后续提交。
- 为 Release Candidate 创建清晰提交，不需要每次提交前询问。

### 不允许自主执行

- 重新设计或“优化”上游 UI。
- 格式化整套上游源码。
- 为让诊断归零而重构锁定主题。
- 猜测用户未提供的番剧、小说、技术栈、XP 或个人经历。
- 购买服务、申请账号、创建 API 密钥或同意外部条款。
- 把公开仓库等同于拥有复制和再发布授权。
- 在没有明确权利确认时部署包含上游文章、角色图、音乐、Live2D 等内容的生产版本。
- 创建新的 Sites 项目或改写现有项目 ID。

### 只在以下情况停止

1. 所有本地 Release Candidate 工作已经完成，但再发布权利仍未被明确确认。
2. 需要不可逆或明显超出当前范围的外部操作。
3. 同一真实阻塞在穷尽安全替代方案后仍无法推进。

不要因为一个检查失败就立即停下；先定位、修复或建立可信降级，再继续后续独立工作。

## 五、Batch 1.1：正常动态与 HOME 视频实测

### 5.1 建立不受系统“减少动态效果”污染的浏览器上下文

优先使用项目已有的 Playwright/浏览器工具，显式创建：

- `reducedMotion: "no-preference"`
- 桌面视口 `1440×900`
- 手机视口 `390×844`
- 页面处于前台可见状态
- 浏览器允许静音媒体自动播放

不要把 HTML 属性存在当成运行验证。

### 5.2 正常动态模式断言

在 HOME 中验证：

- 恰好存在 1 个目标 HOME `<video>`。
- `autoplay`、`muted`、`loop`、`playsinline` 均存在，运行时 `video.muted === true`。
- 视频资源可加载，`readyState >= 2`。
- 首次稳定渲染后 `paused === false`。
- 连续观察 2 秒时，`currentTime` 有明显增加。
- 在 10 秒边界前后确实回绕，不播放原视频结尾。
- 页面从 HOME → 其他页 → HOME 三轮后仍只有 1 个视频实例。
- 切换标签页或 visibility 状态后，回到前台能够按原生命周期恢复。
- 视频画面不是由错误的超大缩放制造局部模糊；桌面和手机裁切均可接受。
- 海报只承担加载/降级，不覆盖正常播放状态。

保留证据：

- 运行时 JSON 断言结果。
- HOME 在约 `0.5s`、`5s`、`9.5s`、回绕后的 `10.5s` 四个时间点的截图。
- 一段短录屏或连续帧索引，足以证明背景实际运动。

### 5.3 减少动态模式断言

另建 `reducedMotion: "reduce"` 上下文，验证：

- 视频暂停或降级为海报。
- 核心信息、导航、资料卡仍可访问。
- 关闭动效不会导致布局错位或空白舞台。

### 5.4 失败时的最小修复边界

如果正常动态模式仍不自动播放，只允许在现有 HOME 视频生命周期附近做最小修复：

- 在媒体 ready、`astro:page-load`、`pageshow` 或恢复可见时调用安全的 `play()`。
- 同时设置 `muted` 属性、运行时 `muted` 和必要的 `defaultMuted`。
- 自动播放被浏览器拒绝时提供一次不遮挡主体的首个用户手势恢复，不弹出新的大按钮。
- 在 `astro:before-swap` 或现有清理路径移除监听、计时器和异步任务。
- 不复制第二套路由或视频状态系统。
- 不改变上游 hero 其余 DOM、层级、CSS 和动效节奏。

每个修复都必须先有失败证据，再有修复后的同一断言通过证据。

技术上的“允许创建提交并发布到现有站点”已经给出，但它不等同于用户确认拥有上游源码和第三方素材的再发布权。

只有用户在当前或后续对话中明确表达类似以下意思，才能判定：

`RIGHTS_CONFIRMED = YES`

> 我确认自己已获得或自行承担 Yuimi 上游源码、文章、图片、音乐、Live2D 等相关内容的复制与公开发布权利，并授权部署到现有站点。

以下说法不能当成权利确认：

- “这是开源的。”
- “仓库是公开的。”
- “可以发布站点。”
- “继续做。”
- 之前对纯技术部署操作的授权。

如果没有明确确认：

- 不要在执行开头停下询问。
- 先完成全部本地 Release Candidate 工作和提交。
- 到最后只问一次上述权利确认。
- 给出已准备好的提交、构建产物、报告和部署前最后一步。
